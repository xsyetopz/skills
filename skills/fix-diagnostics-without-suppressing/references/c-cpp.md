# C and C++

Read when GCC, Clang, MSVC, clang-tidy, clangd, CMake, or xmake reports a diagnostic. Every form
below is a suppression or a loosened check: refuse it, or ask the user first.

Versions checked on 2026-10-06:

| Tool | Version |
| --- | --- |
| GCC | 16.2 (also 16.1, 15.3, 14.4, 13.5) |
| LLVM (Clang, clang-tidy, clangd) | 23.1.2 |
| MSVC Build Tools | 14.50 (`_MSC_VER` 1950, LTS), 14.51 (1951, default since May 2026) |
| CMake | 4.4.4 |
| xmake | 3.1.1 |

The Clang, clang-tidy, and clangd pages are the trunk ("latest") docs, not pinned to 23.1.x, so
check a flag against the installed `--version` before you rely on it.

## GCC

Docs: <https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html>.

### Suppression Forms to Refuse

| Form | Effect, per the docs |
| --- | --- |
| `#pragma GCC diagnostic ignored "-Wx"`, `push`, `pop` | Changes the disposition of a diagnostic and overrides command-line options |
| `#pragma GCC diagnostic ignored_attributes "vendor::attr"` | Hides unknown-attribute warnings |
| `-w`, `--no-warnings` | "Inhibit all warning messages." |
| `-Wno-pragmas` | Stops warnings about bad pragmas, so it hides a broken suppression pragma too |
| `-Wno-deprecated`, `-Wno-deprecated-declarations`, `-Wno-attribute-warning` | Hide those warnings |
| `-isystem dir`, system headers | "All warnings, other than those generated by `#warning`, are suppressed" in a system header |

`-Wsystem-headers` does the opposite: it reports system-header warnings as if they were in user
code. Use it to see what a system-header path hides.

### Config Keys That Loosen Checks

- Removing `-Werror`.
- `-Wno-error=foo`: "makes `-Wswitch` warnings not be errors, even when `-Werror`". `-Werror=foo`
  implies `-Wfoo`; `-Wno-error=foo` does not.
- Any `-Wno-*` flag.

`-fmax-errors=n` and `-Wfatal-errors` change how many errors one run prints, not what is checked.

### Stale Suppressions

GCC documents no warning for a pragma that suppresses nothing. `-Wunknown-pragmas` and
`-Wno-pragmas` cover bad or unknown pragmas only. A `pop` without a `push` restores the
command-line options.

### Deprecations and Replacements

- `__attribute__((deprecated))` and `deprecated ("msg")`: the warning shows the declaration's
  location and the message. GCC documents no replacement argument. Read the message and the
  declaration, then the library's release notes. Docs:
  <https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html#index-deprecated>.
- Explicit `-Wdeprecated` in C++ also enables `-Wcomma-subscript`, `-Wvolatile`,
  `-Wdeprecated-enum-float-conversion`, `-Wdeprecated-enum-enum-conversion`,
  `-Wdeprecated-literal-operator`, and `-Wdeprecated-variadic-comma-omission`.

### Strict CI Form

Keep `-Werror`. Do not add `-Wno-error=*`. Add `-Wsystem-headers` only when the task asks for it.

## Clang

Docs: <https://clang.llvm.org/docs/UsersManual.html>.

### Suppression Forms to Refuse

| Form | Effect, per the docs |
| --- | --- |
| `#pragma clang diagnostic`, `#pragma GCC diagnostic` | Synonyms; `push` and `pop` save and restore the full diagnostic state |
| `-w` | "Disable all warning diagnostics. Errors are still emitted." With `-Weverything`, disabling all warnings wins |
| `-Wno-foo` | Disables warning `foo` |
| `--warning-suppression-mappings=foo.txt` | "Suppress certain diagnostics for certain files." Refuse it like a pragma |
| `#pragma clang system_header` | No warnings from that point to the end of the file |
| `-isystem`, `--system-header-prefix=`, `--no-system-header-prefix=` | A file found in an `-isystem` path is a system header, and warnings in system headers are suppressed |
| `_CLANG_DISABLE_CRT_DEPRECATION_WARNINGS` | Disables deprecation warnings in Clang-provided C runtime headers |

### Config Keys That Loosen Checks

- Removing `-Werror`.
- `-Wno-error=foo`: "Turn warning 'foo' into a warning even if `-Werror` is specified."
- `-Weverything` is not recommended in general; the docs prefer `-Wall -Wextra`. If a project
  uses it, fix or disable each new diagnostic with its `-Wno-` flag. Disabling is a loosening, so
  ask.

### Stale Suppressions

Clang documents no warning for a pragma that suppresses nothing. The only related note in the docs
is that Clang does not support GCC's behavior for a `pop` with no matching `push`.

### Deprecations and Replacements

- `[[deprecated("msg")]]` and `[[gnu::deprecated("msg")]]` take one optional message. Docs:
  <https://clang.llvm.org/docs/AttributeReference.html#deprecated>.
- `__attribute__((deprecated("message", "replacement")))`: the second argument lets the compiler
  offer a Fix-It that replaces the deprecated name.
- `__attribute__((availability(... replacement=string-literal)))` also gives a Fix-It that
  replaces the deprecated declaration.

### Strict CI Form

Keep `-Werror` with `-Wall -Wextra`. Do not add `-Wno-error=*` or `-w`.

## MSVC

Docs: <https://learn.microsoft.com/en-us/cpp>.

### Suppression Forms to Refuse

| Form | Effect, per the docs |
| --- | --- |
| `/W0`, `/w` | "/W0 suppresses all warnings." |
| `/wdnnnn` | Suppresses warning nnnn (for example `/wd4326`) |
| `#pragma warning(disable : nnnn)`, `push`, `pop` | Disables the warning; also accepts `justification : "..."` (VS 2022 17.14; scope unverified) |
| `#pragma warning(suppress : nnnn)` | Disables the warning for the next line |
| `[[gsl::suppress("bounds.1")]]`, `[[gsl::suppress("26400")]]` | Suppresses C++ Core Check warnings on an expression or block |
| `/external:anglebrackets`, `/external:I`, `/external:env:var`, `/external:W0` | Treat headers as external; "`/external:W0` effectively turns off warnings for external headers" |
| `/analyze-` | Turns code analysis off; code analysis is off by default |
| `_CRT_SECURE_NO_WARNINGS`, `_CRT_SECURE_NO_WARNINGS_GLOBALS` | Disable CRT deprecation (C4996) |
| `_SILENCE_*_DEPRECATION_WARNING` | Disable the STL deprecation warning named in the message |

`/wennnn` (treat warning nnnn as an error) and `/wonnnn` (report it once) change the level of a
single warning.

### Config Keys That Loosen Checks

- Lowering `/W4` or `/Wall`. The docs recommend `/W4` for all compilations.
- Removing `/WX`. The docs say it may be best for a new project to use `/WX` in all compilations.
  The linker has its own `/WX`.
- `#pragma warning(once : nnnn)`, which reports a warning only once.

### Stale Suppressions

The pages read document no diagnostic for a `#pragma warning` or `[[gsl::suppress]]` that
suppresses nothing.

### Deprecations and Replacements

- C4996: "deprecation messages usually include a suggested replacement"; the docs usually
  recommend changing the code to use the suggested function. Docs:
  `error-messages/compiler-warnings/compiler-warning-level-3-c4996` under the MSVC docs root.
- For a CRT warning, use the suggested `_s` or Microsoft-named function, or a standard replacement,
  not `_CRT_SECURE_NO_WARNINGS`.
- For an STL warning, the macro name is in the message, but the macro only silences it. Change the
  code (for example, stop deriving from `std::iterator`).
- `__declspec(deprecated("msg"))` and `[[deprecated]]` both raise C4996 on use. Docs:
  <https://learn.microsoft.com/en-us/cpp/cpp/deprecated-cpp>.

### Strict CI Form

`cl /W4 /WX`, with `/external:anglebrackets /external:W0` only if the user approves hiding
third-party header warnings. If `/external:W` is not given, D9007 warns that the other `/external`
options are ignored. Overriding code analysis with `/analyze-` gives D9025.

## clang-tidy

Docs: <https://clang.llvm.org/extra/clang-tidy/index.html>.

### Suppression Forms to Refuse

- `NOLINT`, `NOLINTNEXTLINE`, `NOLINTBEGIN` and `NOLINTEND`. `NOLINT` applies to its own line and
  takes a check list in parentheses, which may use globs.
- Whitespace between `NOLINT` and `(` makes it a bare `NOLINT`, which suppresses every check.
  Watch for this in existing code.
- The docs prefer a check-specific fix. For example, `bugprone-use-after-move` is silenced by
  re-initializing the variable. The docs also say to explain the motivation when suppressing.

### Config Keys That Loosen Checks

| Key | Loosens when |
| --- | --- |
| `Checks: '-foo'`, `--checks=` | A negative glob disables a check |
| `WarningsAsErrors`, `--warnings-as-errors=` | Emptied (`WarningsAsErrors: ''`) or narrowed |
| `HeaderFilterRegex`, `--header-filter` | Narrowed; the default `.*` shows all non-system headers |
| `ExcludeHeaderFilterRegex`, `--exclude-header-filter` | Set; it hides header diagnostics |
| `--line-filter` | Set; it restricts to line ranges |
| `--removed-arg=<string>` | Used; it can change the analyzed code and cause false positives or negatives |

`SystemHeaders` and `--system-headers` ("Display the errors from system headers") is stricter when
true; the default is false.

### Stale Suppressions

clang-tidy documents only a pairing check: every `NOLINTBEGIN` needs a matching `NOLINTEND`, and
`NOLINTBEGIN(check)` pairs only with `NOLINTEND(check)`. A violation produces a `clang-tidy-nolint`
error. The docs read describe no diagnostic for a `NOLINT` that suppresses nothing.

`--verify-config` checks that each check and option in the config files is recognized, which
catches stale check names in `.clang-tidy`.

### Deprecations and Replacements

The research found no clang-tidy page on deprecations or replacements. For a deprecation reported
by the compiler, use the compiler section above.

### Strict CI Form

`--warnings-as-errors=` takes the same format as `-checks` and is appended to the config's
`WarningsAsErrors`. Do not empty or narrow it, and add no new `NOLINT`.

## clangd

Docs: <https://clangd.llvm.org/config.html>.

### Suppression Forms to Refuse

`Diagnostics: Suppress:` takes `'*'` ("to disable all diagnostics"), clangd codes, clang codes such
as `-Wunused-result`, categories, and clang-tidy check names. It is "a simple filter".

### Config Keys That Loosen Checks

- `ClangTidy: Remove:` disables checks (globs allowed) and "takes precedence over Add".
- `UnusedIncludes: None` turns off unused-include diagnostics. `Strict` is the default since
  clangd 17.
- `MissingIncludes: None` is the default; `Strict` is stricter.
- `FastCheckFilter: Strict` (default) runs only checks measured to be fast, so some checks never run
  in clangd unless it is `Loose` or `None`.
- `CompileFlags: Remove: [-W*]` strips warning flags, including `-Werror`, from clangd's view.

clangd settings merge with `.clang-tidy`, with clangd configs taking precedence.

### Stale Suppressions

The config and features pages describe no stale-suppression feature. `UnusedIncludes` reports
unused `#include` lines, not suppressions.

### Deprecations and Replacements

clangd shows the compiler's and clang-tidy's diagnostics, so use the Clang and clang-tidy sections.

## CMake

Docs: <https://cmake.org/cmake/help/latest>.

### Config Keys That Loosen Checks

- `--compile-no-warning-as-error` ignores the `COMPILE_WARNING_AS_ERROR` property and the
  `CMAKE_COMPILE_WARNING_AS_ERROR` variable (3.24). `--link-no-warning-as-error` does the same for
  `LINK_WARNING_AS_ERROR` (4.0).
- `-Wno-error=<category>` demotes a CMake diagnostic category to at most WARN.
- `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` (4.0): a stopgap for third-party projects you cannot edit.
  The docs say a project should not set it in its own code to set its own policy version. It hides
  the old-policy problem rather than fixing it.
- The `SYSTEM` target property (3.25) makes a target's `INTERFACE_INCLUDE_DIRECTORIES` system
  include dirs for consumers; imported targets default to true. The docs do not say what the
  compiler then hides.

### Deprecations and Replacements

- CMake 4.0 removed compatibility with versions older than 3.5: a `cmake_minimum_required(VERSION)`
  or `cmake_policy(VERSION)` below 3.5 is an error. Since 3.31, compatibility with versions older
  than 3.10 is deprecated.
- Fix it in the project: `cmake_minimum_required(VERSION 3.10...4.4)`, the form
  `VERSION <min>[...<policy_max>]`. `policy_max` only states the highest CMake version the project
  has been actively updated for, so do not raise it without testing. Docs:
  <https://cmake.org/cmake/help/latest/command/cmake_minimum_required.html>.
- `-Wdev` and `-Wno-dev` are deprecated since 4.4 as synonyms for `-Wauthor` and `-Wno-author`.

### Stale Suppressions

CMake documents no stale-suppression detection in the pages read.

### Strict CI Form

Set `CMAKE_COMPILE_WARNING_AS_ERROR` to `ON` (3.24) and do not pass `--compile-no-warning-as-error`.
`-Werror=<category>` promotes a CMake diagnostic category to at least SEND_ERROR.
`CMAKE_<LANG>_CLANG_TIDY` (LANG is C, CXX, OBJC, or OBJCXX; 3.6) runs clang-tidy per target, and
`CMAKE_EXPORT_COMPILE_COMMANDS` (3.5) writes `compile_commands.json` for clang-tidy and clangd.

## xmake

Docs: <https://xmake.io>.

### Config Keys That Loosen Checks

`set_warnings(...)` takes `none`, `less`, `more`, `all`, `extra`, `pedantic`, `everything`, and
`error`. `none` maps to `-w` or `-W0`. `all` maps to `-Wall` or `-W3`; `allextra` to `-Wall -Wextra`
or `-W4`; `error` to `-Werror` or `-WX`. Lowering the level or dropping `"error"` loosens the check.
`set_warnings("all", "error")` is the strict form; with no target it is global. Docs:
<https://xmake.io/api/description/project-target.html>.

### Stale Suppressions

xmake documents no stale-suppression detection. `xmake check` validates `xmake.lua` API values
(for example an unknown `set_languages("c91")`), compiler flags, and missing include dirs; it does
not look at suppressions.

### Deprecations and Replacements

The research found no page on how xmake reports deprecated `xmake.lua` APIs. `xmake check api` (and
`xmake check -v`) is the closest documented mechanism.

### Strict CI Form

xmake does not echo warnings in real time by default. Use `set_policy("build.warning", true)`
(since 2.6.8), `xmake -w`, or `xmake g --build_warning=y`. For clang-tidy, run
`xmake check clang.tidy` (options `--list`, `--checks="*"`, `-f src/main.c`); it runs
`clang-tidy -p compile_commands.json`. `xmake project -k compile_commands` writes the compilation
database. Docs: <https://xmake.io/api/description/builtin-policies.html> and
<https://xmake.io/guide/extensions/builtin-plugins.html>.

## Finding the Flag and the Notes

- Clang prints the flag, such as `[-Wextra-tokens]`, because `-fdiagnostics-show-option` is on by
  default. GCC prints it too; `-fno-diagnostics-show-option` turns it off. Use it to find the
  rule's docs, not to add a `-Wno-` flag.
- Read the `note:` lines under an error. Clang prints notes such as `note: candidate function not
  viable`. For templates, `-ftemplate-backtrace-limit=n` caps instantiation notes (default 10 in
  both GCC and Clang; 0 removes the cap in Clang). Read the note that points at your code first;
  set the limit to 0 only when the chain is cut off.
- Structured output: GCC `-fdiagnostics-format=sarif-stderr` or `sarif-file` (the GCC 16 docs list
  `text`, `sarif-stderr`, and `sarif-file`). Clang `-fdiagnostics-format=sarif` is "currently
  unstable"; use `-Wno-sarif-format-unstable -fno-caret-diagnostics` and `2> diagnostics.sarif`.
  MSVC `/experimental:log filename` writes a `.sarif` file. MSVC `/diagnostics:caret` shows the
  source line and caret.
