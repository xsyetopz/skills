## XenonRecomp

MIT, last commit 2025-08-04 (`ddd128bc`), no releases. It builds with CMake 3.20+ and Clang 18+;
other compilers are "not recommended, including for recompilation output". The README disclaimer:
"This project does not provide a runtime implementation... Making the game work is your
responsibility."

CLI:

- `XenonAnalyse [input XEX] [output jump-table TOML]`
- `XenonRecomp [config.toml] [path to XenonUtils/ppc_context.h]`

XenonTests recompiles Xenia's PPC tests.

## Config

`[main]` keys from the README and `recompiler_config.cpp`:

- Paths: `file_path`, `patch_file_path` (xexp), `patched_file_path` (auto-created),
  `out_directory_path` (must exist), `switch_table_file_path`.
- Optimization flags, all default false: `skip_lr`, `skip_msr`, `ctr_as_local`, `xer_as_local`,
  `reserved_as_local`, `cr_as_local`, `non_argument_as_local`, `non_volatile_as_local`. The README
  says to enable them only after a working recompilation.
- Helper addresses: `restgprlr_14_address`, `savegprlr_14_address`, `restfpr_14_address`,
  `savefpr_14_address`, `restvmx_14_address`, `savevmx_14_address`, `restvmx_64_address`,
  `savevmx_64_address`. Each has a documented byte pattern, for example `restgprlr_14` is
  `e9 c1 ff 68`. There is no auto-detect: "These functions could likely be auto-detected, but there
  is currently no mechanism".
- `setjmp_address`, `longjmp_address`. Remove them if the game does not use them.
- `functions = [{ address, size }]`: explicit function boundaries.
- `invalid_instructions = [{ data, size }]`: skips exception data and padding, for example
  `{ data = 0x00000000, size = 4 }` in the Unleashed config.
- `[[midasm_hook]]` keys: `name`, `address`, `registers`, `return`, `return_on_true`,
  `return_on_false`, `jump_address`, `jump_address_on_true`, `jump_address_on_false`,
  `after_instruction`. The hook is a C++ function such as
  `void IndexBufferLengthMidAsmHook(PPCRegister& r3)`.
- Switch tables TOML, generated by XenonAnalyse: `[[switch]]` with `base`, `r`, `default`, and
  `labels`.

Examples: UnleashedRecomp's `SWA.toml` (all optimizations true, 191 `midasm_hook` occurrences) and
`SWA_switch_tables.toml`.

## Function Discovery

`.pdata` gives boundaries for functions with stack space. For others the analyzer finds starts
through branch-link targets and works out the length by static analysis.

It struggles with functions that contain jump tables, because they look like tail calls. The
workaround is a manual `functions` entry. Unleashed's `SWA.toml` comments these as functions that
"do not exist in .pdata and do not analyze properly due to having jump tables".

## Jump Tables

- Detection searches for `mtctr r0` followed by `bctr`. The logic is tuned to Sonic Unleashed:
  "there is no fully generic solution... may require modifications to the detection logic".
- A table with no `[[switch]]` entry prints
  `Found a switch jump table at {:X} with no switch table entry present`.
- A bad table prints `ERROR: Switch case at {:X} is trying to jump outside function`.
- Fix both in the switch TOML or the `functions` list, then regenerate.

## Memory, Endianness, and Floats

- CPU state is passed as `ctx` and `base`. Instruction implementations work on little-endian values;
  loads and stores byte-swap, and all of them are volatile so Clang does not reorder them.
- Vectors are handled by reversing the whole 16-byte vector, so dot products use WZY.
- FPU denormals are kept but VMX flushes them, tracked by the fpscr flush mode in the context.
- VMX uses x86 intrinsics; ARM64 goes through simde.
- Indirect calls use a "perfect hash table": the function pointer is at `base + guest_addr * 2`,
  placed after the XEX memory region.

## Known Limits

- MMIO (for example XMA) is unimplemented. Exceptions are unsupported (the link register and
  handlers that jump anywhere).
- Some D3D pack and unpack instructions do not support all operand types and print
  `Unexpected D3D color pack instruction` or `Unexpected float16_4 pack instruction`.
- `blrl` and `vcmpbfp`/`vcmpbfp128` emit `__builtin_debugtrap();`. Some other pack-instruction
  default branches also emit a trap; the full list was not checked.
- Log lines: `Unrecognized instruction at 0x...`, `Unable to decode instruction`,
  `Function at {:X} ends prematurely with instruction ...`, and
  `has RC bit enabled but no comparison was generated`.
- The README says missing instructions are mostly variants of already implemented ones.

## Overrides

Functions are emitted as weak aliases to `__imp__sub_XXXXXXXX`:

```cpp
PPC_FUNC_IMPL(__imp__sub_XXXXXXXX);
PPC_FUNC(sub_XXXXXXXX) { __imp__sub_XXXXXXXX(ctx, base); }
```

Define your own `PPC_FUNC(sub_XXXXXXXX)` in a separate source file to replace a function, and call
`__imp__sub_XXXXXXXX` for the original. Use `[[midasm_hook]]` to inject inside a function.

## XenosRecomp

MIT, last code commit 2025-08-03 (`990d03b2`), no releases. It converts Xbox 360 shader binaries to
HLSL; DXC then produces DXIL and SPIR-V. The README says: "Users are expected to modify the
recompiler to fit their needs. Do not expect the recompiler to work out of the box." Unleashed-
specific code is under the `UNLEASHED_RECOMP` macro.

- Unimplemented: integer constants, dynamic register indexing, mini vertex fetch, 1D textures and
  some texture-fetch features (LOD, sampler filters), memory export, and point size.
- Control flow is a `while` plus `switch` on a `pc` variable, because HLSL has no goto.
- Vertex endian swap: 16-bit formats are swizzled to YXWZ and fixed with `g_SwappedTexcoords`.
  `R11G11B10` is unpacked through a specialization constant.

## UnleashedRecomp

GPL-3.0, release v1.0.3 (2025-04-03), last commit 2026-06-29. Build (`docs/BUILDING.md`): clone with
submodules, copy `default.xex`, `default.xexp`, and `shader.ar` into `UnleashedRecompLib/private/`,
and use VS2022 with Clang (Windows), apt or pacman packages (Linux), or Xcode 16.3+ (macOS).

Legal: "This project does not include any game assets. You must provide the files from your own
legally acquired copy of the game". The installer rejects modified files.
