# Headings and links

How a Markdown file on GitHub is navigated: headings, the anchors GitHub
generates from them, the linked Contents list, links to other files and
images, and the short references GitHub links by itself. Quotes come from
GitHub Docs, [Basic writing and formatting syntax][basic] and
[Autolinked references and URLs][autolink], and from the
[GFM spec][spec] (version 0.29-gfm).

## Headings as the outline

**Definition.** An ATX heading is one to six `#` characters, a space, and
the heading text. GitHub: "The number of # you use will determine the
hierarchy level and typeface size of the heading." One `#` title per file,
then `##` sections, then `###` inside them, never skipping a level.

**Use when.**

- Every section a reader or agent might jump to, search for, or link.
- A bold line stands where a heading belongs; convert it to a heading.

**Do not use when.**

- The text is a label inside a card or list (**Definition.**, **Use
  when.**); a heading there floods the outline with repeated entries.
- Two sibling headings would have the same text; rename one, since the
  second anchor gets a `-1` suffix that nobody guesses.

**Example.**

```markdown
# Release process

## Prepare the branch

### Update the version

## Publish
```

**Cost removed.** A file whose sections cannot be found by `grep -n '^#'`,
listed in GitHub's outline, or linked by anchor.

**Verify.** `grep -nE '^#{1,6} ' FILE` prints the outline in order with no
skipped level. Lint rules MD001, MD003, MD024, MD025, and MD036 pass
([lint rule map](agent-readable-and-lint.md#lint-rule-map)).

## Section links and heading anchors

**Definition.** GitHub gives every heading an anchor. Its rules, quoted:
"Letters are converted to lower-case." "Spaces are replaced by hyphens
(-). Any other whitespace or punctuation characters are removed."
"Markup formatting is removed, leaving only the contents (for example,
`_italics_` becomes italics)." "If the automatically generated anchor for a
heading is identical to an earlier anchor in the same document, a unique
identifier is generated by appending a hyphen and an auto-incrementing
integer."

**Use when.** Linking to a section in the same file (`#anchor`) or in
another file (`path.md#anchor`).

**Do not use when.** The target has no heading; add a
[custom anchor](#custom-anchors) instead of linking to a nearby heading.

**Example.** GitHub's own sample:

```markdown
## This'll be a _Helpful_ Section About the Greek Letter Θ!

[Link Text](#thisll-be-a-helpful-section-about-the-greek-letter-Θ)
```

The apostrophe and `!` are removed, `_` markup is removed, spaces become
hyphens, and the non-ASCII letter stays.

**Cost removed.** Links that open the top of the page instead of the
section. GitHub warns: "If you edit a heading, or if you change the order
of headings with "identical" anchors, you will also need to update any
links to those headings as the anchors will change."

**Verify.** After renaming a heading, search the repository for the old
anchor (`rg -n '#old-anchor'`) and fix every hit. markdownlint MD051 checks
fragments within one file; a link checker or a rendered view checks links
across files.

## Linked Contents list

**Definition.** A `## Contents` section right after the file's intro
paragraph, holding one link per `##` heading, in order:
`- [Heading text](#anchor)`. GitHub already shows an "Outline" menu: "When
you use two or more headings, GitHub automatically generates a table of
contents that you can access by clicking the "Outline" menu icon within
the file header." That menu exists only in the rendered view. An agent or
raw reader that reads the first lines of a file sees the Contents list,
learns the file's scope, and jumps by anchor.

**Use when.**

- A reference, guide, or README longer than about 100 lines, or with more
  sections than fit on one screen.
- A file agents read in part (`head`, a line range, a preview).

**Do not use when.**

- The file is short enough to read whole; the list only repeats headings.
- The list would be unlinked plain text; an unlinked list cannot be
  followed and is not checked by MD051 when a heading changes.

**Example.**

```markdown
# Deploy guide

How to build, release, and roll back the service.

## Contents

- [Build](#build)
- [Release](#release)
- [Roll back](#roll-back)

## Build
```

**Cost removed.** A reader loading the first 30 lines of a 400-line file
without knowing what else it covers, and hand-kept lists that drift from
the headings.

**Verify.** The bundled script regenerates or checks the list:

```sh
python3 scripts/markdown_toc.py FILE.md
python3 scripts/markdown_toc.py --check FILE.md
python3 scripts/markdown_toc.py --max-level 3 FILE.md
```

It rewrites the list under an existing `## Contents` heading from the
headings of levels 2 to N (default 2), nested two spaces per level. An
entry longer than `--width` (default 80, markdownlint's MD013 default)
becomes `[Heading text][toc-1]` with a `[toc-1]: #anchor` definition after
the list, because MD013 exempts definition lines. The script owns the
`toc-` label prefix and removes stale `toc-` definitions. `--check` exits
1 when a list is stale; exit 2 means bad input or a file without a
`## Contents` heading, and the other files are still processed. Then run
markdownlint (MD051, MD052, MD053).

## Custom anchors

**Definition.** An HTML anchor gives a link target to text with no
heading: "You can use standard HTML anchor tags
(`<a name="unique-anchor-name"></a>`) to create navigation anchor points
for any location in the document." Link to it as `#unique-anchor-name`.

**Use when.** A stable link must point at a paragraph, table row, or list
item that should not become a heading.

**Do not use when.**

- The target deserves a heading; GitHub: "Custom anchors will not be
  included in the document outline/Table of Contents."
- The name could collide with a heading anchor; GitHub advises "a unique
  naming scheme for anchor tags, such as adding a prefix to the name
  attribute value."

**Example.**

```markdown
<a name="faq-proxy"></a>
Set `HTTPS_PROXY` before running the installer behind a proxy.

See [the proxy note](#faq-proxy).
```

**Cost removed.** Links to "the paragraph under the second table", which
readers cannot follow.

**Verify.** `rg -n 'name="faq-proxy"' FILE` finds exactly one anchor, and
the rendered link scrolls to it.

## Relative links

**Definition.** A link or image path relative to the current file:
"Links starting with / will be relative to the repository root. You can
use all relative link operands, such as ./ and ../." GitHub rewrites them
for the branch being viewed.

**Use when.** Linking to any file or directory in the same repository.

**Do not use when.** The target is outside the repository; use its full
URL. Do not write `https://github.com/org/repo/blob/main/...` for a file
in the same repository: "Absolute links may not work in clones of your
repository - we recommend using relative links to refer to other files
within your repository."

**Example.**

```markdown
[Contribution guidelines](docs/CONTRIBUTING.md)
[Install steps](../INSTALL.md#linux)
```

Keep the link text on one line; GitHub states a link whose text spans two
lines "will not work".

**Cost removed.** Links that point at `main` while a reader browses a
tag, a fork, or a local clone.

**Verify.** Every target exists: resolve each path from the file's
directory (`test -e`), and each `#anchor` against the target's headings.

## Reference-style links

**Definition.** A link written `[text][label]` whose URL is defined once
in a line `[label]: URL`. The GFM spec: "Link reference definitions can
come either before or after the links that use them." Label matching is
case-insensitive, and "If there are several matching definitions, the
first one takes precedence."

**Use when.**

- A long URL would push a prose line past the line-length limit.
- The same URL is cited more than once in a file.

**Do not use when.** The link is short and used once in a table cell; an
inline link keeps the cell self-contained.

**Example.**

```markdown
Anchors follow the [GitHub rules][gh-anchors].

[gh-anchors]: https://docs.github.com/en/get-started/writing-on-github
```

Put all definitions at the end of the file so the prose reads cleanly and
the sources are listed in one place.

**Cost removed.** Prose broken by 120-character URLs, and one URL edited
in three places.

**Verify.** markdownlint MD052 (every label defined) and MD053 (every
definition used) pass.

## Images with alt text

**Definition.** `![alt text](path)` displays an image. GitHub: "Alt text
is a short text equivalent of the information in the image." For images
in the repository, "use relative links instead of absolute links."

**Use when.** A screenshot, diagram export, or badge carries information.

**Do not use when.**

- The image shows text or code that could be written as text; write the
  text, which agents and search can read.
- The diagram can be a [Mermaid block](github-extensions.md#mermaid-diagrams)
  that stays editable in the diff.

**Example.**

```markdown
![Settings page with the Branch protection tab selected](docs/img/rules.png)
```

Describe what the image shows and why it matters, not "screenshot" or
"image".

**Cost removed.** An image that is empty to screen readers and to agents
reading the raw file.

**Verify.** markdownlint MD045 passes, and each relative image path
exists.

## Autolinked references

**Definition.** In conversations GitHub turns short references into
links: issue and pull request numbers (`#26`, `GH-26`,
`owner/repo#26`), commit SHAs (`a5c3785`, `user@SHA`,
`owner/repo@SHA`), and `@username` mentions. Plain URLs also become links.
GitHub: "Autolinked references are not created in wikis or files in a
repository."

**Use when.** Writing issues, pull request descriptions, comments, and
commit messages that point at other work.

**Do not use when.** Writing a `.md` file in the repository: `#123` stays
plain text there. Write a full link instead. Mentions in comments notify
people; do not add `@name` just to credit someone.

**Example.**

```markdown
Fixed in [#123](https://github.com/octo-org/app/pull/123).
```

In a comment, `Fixed in #123.` is enough.

**Cost removed.** Dead `#123` text in a README, and unwanted
notifications.

**Verify.** In a repository file, `rg -n '(^|\s)#[0-9]+\b' FILE` finds no
bare issue numbers; markdownlint MD034 flags bare URLs, which should be
`<https://...>` or a link with text.
